## Этап 1. Скелет

Цель: API без воркера и очередей. Сохранить URL, получить одну общую страницу на все варианты адреса, разложить сохранения по личному дереву папок. Тесты на настоящем Postgres, запуск одной командой, CI.

### B. Схема данных

- [x] 2.1 🎓 — Схема [db/schema.dbml](db/schema.dbml), запросы и индексы [db/queries.md](db/queries.md), ADR 005.
- [ ] 2.2 — Схема в Drizzle (`src/database/schema`), первая миграция (`src/database/migrations`).
  Готово: на пустой базе `db:migrate` создаёт всю схему, повтор ничего не меняет; в `migration.sql` есть все ключи, ограничения и индекс из `schema.dbml`, в том числе `ON DELETE SET NULL (folder_id)` и `NULLS NOT DISTINCT`; файлы миграции в git.
- [ ] 2.3 — Тестовые пользователи.

- [ ] 2.4 🎓 — Окружение интеграционных тестов на настоящем Postgres.
  Покрывает: откуда берётся база (контейнер из теста или Compose); изоляция при параллельном запуске; очистка таблиц или откат транзакции — с учётом теста на гонку (4.5), которому нужны настоящие параллельные транзакции.
  Готово: пример теста пишет в базу и читает; набор проходит три раза подряд одинаково.

### C. Нормализация адреса

- [ ] 3.1 🎓 — Таблица примеров «вход → выход», не меньше 20 строк.
  Покрывает: каждое правило из requirements, раздел 4; завершающий слэш, фрагмент `#`, порт по умолчанию, порядок параметров, пустые параметры, домен в верхнем регистре, кириллический домен, схемы не `http`/`https`, не-адрес, адрес длиннее 2048 байт. Спорное — в сторону дубликата, причина в колонке.
  Готово: таблица прошла ревью, ADR 007.
- [ ] 3.2 🎓 — Функция нормализации и unit-тесты по таблице.
  Готово: строка таблицы — тестовый случай; тест повторной нормализации на всей таблице; модуль не импортирует Nest и базу.
- [ ] 3.3 — Ошибка недопустимого адреса.
  Готово: для не-адреса, неподдерживаемой схемы и слишком длинного адреса — ошибка определённого вида, отличимая от сбоя; есть тесты.

### D. Сохранение URL

- [ ] 4.1 🎓 — Контракт эндпоинтов: сохранения (создать, список), папки (создать, переименовать, переместить, удалить, дерево, положить сохранение).
  Покрывает: ответ на повторное сохранение того же адреса (повтор запроса при плохой сети); поля, нужные расширению на этапе 4; есть ли у списка фильтр по папке (ADR 005, индекс `folder_id`).
  Готово: прошёл ревью, записан в `docs/api.md`.
- [ ] 4.2 — Guard `X-User-Id` и декоратор текущего пользователя.
  Готово: без заголовка или с неверным форматом — 401; контроллеры получают пользователя только через декоратор; тесты.
- [ ] 4.3 — Проверка входных данных.
  Готово: неверное тело — 400 с именем поля; недопустимый адрес (3.3) — 400, а не 500.
- [ ] 4.4 🎓 — Сценарий «сохранить URL»: нормализовать, найти или создать страницу и вариант, создать сохранение. Код и `sequenceDiagram` двух одновременных запросов с одним новым адресом.
  Покрывает: что видит каждый запрос между «страницы нет» и «вставил»; кто судья — код или база; границы транзакции; состояние базы при падении посередине. Материал: `INSERT ... ON CONFLICT`.
  Готово: интеграционные тесты — первое сохранение создаёт страницу, вариант и сохранение; тот же адрес с другими `utm_*` у второго пользователя даёт ту же страницу; новое сохранение во «Входящих».
- [ ] 4.5 — Тест на гонку: 20 одновременных сохранений одного нового адреса разными пользователями.
  Готово: одна страница, один вариант, 20 сохранений, ни одного 5xx; 10 запусков подряд; факт в ADR 005.
- [ ] 4.6 — Повторное сохранение того же адреса тем же пользователем.
  Готово: дубликата нет, ответ по контракту 4.1; тест, в том числе на два одновременных запроса.
- [ ] 4.7 — Список сохранений: keyset-пагинация, сортировка по дате.
  Готово: пользователь A не видит сохранений B; порядок стабилен при одинаковой дате; тесты.

### E. Дерево папок

- [ ] 5.1 — Создание и переименование папки.
  Готово: в корне и внутри другой; в чужой — отказ; одноимённая рядом — отказ; тесты.
- [ ] 5.2 🎓 — Получение дерева: рекурсивный запрос или все папки пользователя и сборка в коде.
  Готово: эндпоинт возвращает дерево; тест на три уровня; причина выбора и порог пересмотра — в ADR 011.
- [ ] 5.3 🎓 — Перемещение папки. Код и `sequenceDiagram`.
  Покрывает: проверку одним рекурсивным запросом, что новый родитель не внутри перемещаемой; одновременное перемещение A в B и B в A.
  Готово: тесты — обычное перемещение; в себя, во вложенную, в чужую — отказ; решение по одновременным перемещениям в ADR 011.
- [ ] 5.4 — Удаление папки.
  Готово: вложенные папки удаляются, их сохранения возвращаются во «Входящие» (ADR 005); тесты.
- [ ] 5.5 — Перенос сохранения в папку и во «Входящие».
  Готово: в чужую папку — отказ; тесты.

### F. Запуск и CI

- [ ] 6.1 — Dockerfile и сервис приложения в Compose.
  Решить: кто применяет миграции — один шаг перед запуском экземпляров, не каждый экземпляр при старте; `drizzle-kit` в devDependencies, `.sql` не попадают в `dist`.
  Готово: на чистой копии `docker compose up` поднимает базу и приложение, миграции применены, `/health` — 200; процесс не от root.
- [ ] 6.2 — GitHub Actions: линтер, unit- и интеграционные тесты с Postgres, сборка образа.

- [ ] 6.3 — Корректная остановка.
  Готово: по сигналу приложение дожидается текущих запросов и закрывает пул; шаги проверки записаны.
- [ ] 6.4 — Два экземпляра на разных портах с одной базой.
  Готово: сохранение через первый видно во втором, папка через второй — в первом; факт в ADR 001.
