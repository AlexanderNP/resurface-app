# ADR 012. Личность пользователя на этапе 1: заголовок `X-User-Id` и guard

Статус: принято · Дата: 2026-10-11 · Этап: 1

## Контекст
Целевая схема: шлюз проверяет JWT и передаёт внутрь идентификатор пользователя (requirements, раздел 7). Шлюза на этапе 1 нет, а изоляцию данных пользователей проверять нужно уже сейчас.

## Варианты
| Вариант | За | Против |
| --- | --- | --- |
| Заголовок `X-User-Id` и guard | Совпадает с целевым контрактом шлюза; в тестах можно выступать от разных пользователей | Любой, кто достучался до API, назовётся кем угодно |
| Один идентификатор в коде | Ноль кода | Изоляцию не проверить; при появлении шлюза менять все места |
| JWT внутри API | Ближе к продукту | Не тема этапа; по целевой схеме проверка живёт в шлюзе |

## Решение
Заголовок `X-User-Id`, guard и декоратор параметра. Без заголовка или с неверным форматом — 401.

## Последствия
- API нельзя открывать наружу, пока перед ним нет шлюза.
- Сессий нет: личность приходит с каждым запросом, что нужно для нескольких экземпляров.
- Идентификатор попадает в код через один декоратор: смена источника затронет только guard.

## В продакшене я бы...
Проверял бы JWT на шлюзе и закрыл бы внутренний трафик: подписанный внутренний токен или сетевая изоляция, чтобы заголовок нельзя было подделать в обход шлюза.
