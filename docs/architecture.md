# Архитектура

Документ описывает компоненты системы и технологии: что используется и для чего. Обоснования решений: [requirements.md](requirements.md) и [adr/](adr/). Технологии добавляются по этапам, не все присутствуют с первого дня.

## Компоненты

- **Расширение браузера** — захват страницы в один клик, показ категории и связанного сохранённого.
- **Шлюз** — единая точка входа; проверяет JWT и передаёт внутрь `userId`.
- **API (Nest.js)** — сохранения, дерево папок, поиск, статусы.
- **Воркер** — фоновое получение страницы, извлечение текста, ключевых слов и категории.
- **Индексатор** — переносит данные страниц из Postgres в поисковый индекс.
- **Postgres** — основное хранилище и источник правды.
- **RabbitMQ** — очередь задач.
- **OpenSearch** — полнотекстовый поиск.

## Потоки данных

**Сохранение.** Расширение → шлюз → API → запись в Postgres и постановка задачи в RabbitMQ → ответ клиенту «сохранено». Воркер берёт задачу, получает страницу, обновляет её состояние в Postgres.

**Поиск.** Клиент → шлюз → API → OpenSearch (фильтр: только страницы пользователя) → список с путём в дереве.

**Контекстный возврат.** Расширение присылает URL → API ищет страницу по таблице вариантов адреса → при промахе ставит задачу получения с высоким приоритетом → возвращает связанные сохранённые ресурсы по ключевым словам и тегам.

**Синхронизация индекса.** Воркер в одной транзакции пишет данные страницы и запись в таблицу outbox → отдельный процесс публикует события в RabbitMQ → индексатор идемпотентно обновляет OpenSearch.

## Технологии

| Технология | Для чего | Этап |
| --- | --- | --- |
| TypeScript, Nest.js | API и воркер (одна кодовая база, два процесса) | 1 |
| Postgres | Основное хранилище: пользователи, страницы, сохранения, дерево, таблица вариантов адреса; уникальные ограничения гарантируют идентичность и идемпотентность | 1 |
| Docker, Docker Compose | Окружение разработки: приложение, воркер, Postgres и остальные сервисы | 1 |
| GitHub Actions | CI: линтер, тесты, сборка образа | 1 |
| RabbitMQ | Очередь задач получения страниц: повторы с растущей паузой, аренда задачи, «мёртвая» очередь | 2 |
| OpenSearch | Полнотекстовый поиск по словам внутри страниц, производный индекс от Postgres | 3 |
| Transactional outbox | Надёжная синхронизация Postgres и OpenSearch без записи в оба хранилища подряд | 3 |
| Расширение браузера (Manifest V3, интерфейс на Vue) | Основной клиент: захват страницы, контекстный возврат | 4 |
| k6 | Нагрузочные тесты: поиск точки излома | 5 |
| Redis | Кэш, добавляется только после замеров, показавших проблему | 5 |
| Prometheus, Grafana | Метрики и дашборды | 6 |
| OpenTelemetry | Сквозная трассировка запросов между компонентами | 6 |
| Docker Swarm, затем Kubernetes | Оркестрация, два инстанса приложения за балансировщиком | 8 |
| Vue 3, Vite, vite-plugin-pwa | Веб-сервис и PWA | 9 |

Технология шлюза выбирается на этапе, посвящённом безопасности, и фиксируется в ADR.

## Заменяемые в продакшене компоненты

Решения, принятые из учебных соображений, и их продакшен-альтернативы описаны в ADR: брокер (RabbitMQ вместо BullMQ) и поиск (OpenSearch вместо Postgres full-text search).
