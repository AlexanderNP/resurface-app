# Запросы этапа 1

Пункт 2.1 roadmap, решения — ADR 005. Индексы проектируются от этой таблицы: индекс без запроса, который он ускоряет, только замедляет запись.

## Как заполнять

1. Одна строка — один SQL-запрос, который код (или сама база) выполнит на одном шаге сценария.
2. «Вход» — что известно в момент запроса: пользователь из заголовка, параметры от клиента, результат предыдущего шага. В `WHERE` попадает только вход, в виде параметров `$1`, `$2`.
3. Запрос с `JOIN` — это два поиска: основная таблица по `WHERE` и вторая таблица по ключу соединения. Основная — в колонке «Таблица», вторая — в колонке `JOIN` с колонкой соединения.
4. Индекс (пункт 2.1.3): слева колонки с `=`, затем колонка из `ORDER BY` (документация, 11.3 и 11.4). Если первичный ключ или `UNIQUE` уже начинается с этих колонок — индекс не нужен, напиши, какой ключ его покрывает.
5. Действие при удалении (`CASCADE`, `SET NULL`, `RESTRICT`) — скрытый запрос самой базы к дочерней таблице по колонкам внешнего ключа. Для него тоже нужна строка.
